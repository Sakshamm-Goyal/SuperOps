## Priority findings

1. **P1 — Support verifier accepts an actual forbidden disclosure.** `experiments/support/verifier.py:65-75` trusts the model's `disclosed_customer_ids` declaration; it does not bind `customer_id`, require null denied `order_id`, or inspect/constrain the customer-facing `reply`. Own fixture: authenticated A requests B's order; output says DENY_IDENTITY, customer_id B, order_id O, empty declared disclosures and a reply giving B's address/order status. Actual `accepted=true, critical_failure=false`. Expected rejection/critical disclosure. `workflow.py:64-84` gives lookup tools all order/customer records, so an erroneous model has access to the material it can leak. The quality gate's 'zero critical' claim is therefore unsound even if all sampled cases pass. Fix requires safe output contract/rendering plus independent actual-field/disclosure assertions, with adverse regression cases; simply asking the model to self-report leaks is insufficient.

2. **P1 — 720-hour economic recommendation ignores rate changes and missing coverage.** `greenops/services/plans.py:127-138` obtains only the rate at as_of (`:40-45`) and multiplies it by 720. Own fixture: baseline $0.20/h, candidate $0.10 first hour then $0.30 remaining719 yields claimed +$72 gross/net versus correct -$71.80. Removing the later rate still yields projected $72 candidate cost although only one of720 hours has a rate. Production never invokes the separately unit-tested interval_cost oracle. This can reverse whether a change is beneficial. Same call hardcodes experiment/transition costs0 and defaults optimizer overhead0, so 'net' does not deduct recorded investigation/trial expenditure. Use effective intervals, currency/unit checks, coverage and attributable overhead in the actual plan path; missing amounts must not become zero.

3. **P1/P2 — One failed model case crashes AI results aggregation.** `experiments/support/verifier.py:60-61` returns no `category` for None output. `_ai_trial` unconditionally reads it at `greenops/services/trials.py:165-174`; final evaluator does the same at `experiments/support/evaluate.py:98-101`. Pure reproducer returns `KeyError: 'category'`. In investigation trial.run catches this as generic INCOMPLETE, losing the 40-case breakdown; evaluator exits without aggregate report. Requests/timeouts/schema failures must stay in denominator with category/reason, and incurred model attempts must be persisted even when aggregate construction fails (model_calls insert is only after aggregation at trials.py176-180).

4. **P2 — Production relevant-policy selection is regex-only and drops mandatory return rules on natural phrasing.** `experiments/support/workflow.py:43-56` adds sections5/6/10 only for a fixed word pattern. Own request 'Please provide a prepaid label so I can ship this purchase back to your warehouse.' includes neither standard nor premium return rules. This is real connected-path policy_context code, not just scripted sample logic, and violates the explicit no regex-only semantic routing instruction. Preserve mandatory policy invariants and use a validated bounded intent/retrieval path; expand independent paraphrase coverage.

5. **P1 — Paid evaluator and execution verification calls bypass spend guard.** Static: `experiments/support/evaluate.py:89` calls run_case(..., None) for80 calls plus internal tool/model rounds; `greenops/services/execution.py:65` does so for every post-action AI smoke. AdkGateway budget callback is conditional (`greenops/adapters/model.py:102-105`), and has no max-token generation setting (`:91-92,110-112`). Thus MAX_RUN_COST_USD/MAX_MODEL_CALLS guard the investigation but do not guard these paths. No paid calls were made in this audit. Give each path explicit approved durable budget and cap; include them in costs.
